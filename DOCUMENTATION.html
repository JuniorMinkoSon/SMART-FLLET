🚛 SMART FLEET - Documentation Complète

📋 Vue d'ensemble

SmartFleet est un système complet de gestion de flotte avec 3 rôles distincts, authentification sécurisée, et traçabilité complète.

🔐 Authentification & Sécurité OWASP-10

Flux Login

1. Frontend envoie credentials
POST /api/login
{ "email": "admin@smartfleet.com", "password": "admin123" }

2. Backend valide
✓ Vérifier format email
✓ Vérifier password length (6+ chars)
✓ Rate limiting: max 5 tentatives/15min
✓ Query: SELECT FROM users WHERE email=? AND password=?

3. Response
✓ {id, email, name, role, token}
✗ "Identifiants incorrects" (401 - pas de fuite info)

Tokens & RBAC

Token Format: Simple integer (user_id)
Validation: À chaque requête protégée
Header: Authorization: Bearer {userId}
Check: SELECT FROM users WHERE id=? AND is_active=1

📡 Endpoints API

Authentication

POST /api/login
Identifie utilisateur et retourne token
Rate limit: 5 tentatives/15min
POST /api/register
Crée nouveau compte
Validation: email unique, password 6+ chars, role enum

Vehicles

GET /api/vehicles (All authenticated roles)
Response: [id, code, type, name, plate, status, km, engine_hours, fuel_level]
POST /api/vehicles (Admin, Gestionnaire)
403 si Conducteur
Crée véhicule + logs audit

Missions

GET /api/missions (All roles)
Retourne missions avec statuts: planifiee → en_cours → retour → cloturee
POST /api/missions (Admin, Gestionnaire)
Crée mission + assign vehicle & driver + change statuses
POST /api/missions/:id/departure (Conducteur only)
Record: km, engine_hours, fuel_level
Backend: UPDATE mission status='en_cours', UPDATE vehicle km
POST /api/missions/:id/arrival (Conducteur only)
Record: km, engine_hours, fuel_level
Backend: UPDATE mission status='retour', CREATE alert
POST /api/missions/:id/validate (Admin, Gestionnaire)
Clôture mission: status='cloturee', free vehicle & driver

Alerts & Audit

GET /api/alerts (All roles)
Retourne alertes non lues
GET /api/audit (Admin only)
403 si pas admin
Retourne complete audit trail (500 derniers logs)

🔄 Flux Complet Exemple: Mission

JOUR 1 - Gestionnaire crée mission 
Frontend (email/pwd)
  → POST /api/login
  → Backend: Validate + Query users table
  → Response: {token: 2, role: 'gestionnaire'}
  ✓ Audit log: action='LOGIN'

Frontend (form: site, client, vehicle_id, driver_id)
  → POST /api/missions
  → Backend:
     ✓ Extract token: user_id = 2
     ✓ RBAC check: 'gestionnaire' in ['admin', 'gestionnaire']? YES
     ✓ Validate inputs (email format, ID integers, etc)
     ✓ Check FK: SELECT FROM vehicles WHERE id=1 → Found
     ✓ Check FK: SELECT FROM drivers WHERE id=2 → Found
     ✓ INSERT INTO missions (code, site, client, vehicle_id, driver_id, created_by='2', status='planifiee')
     ✓ UPDATE vehicles SET status='affecte' WHERE id=1
     ✓ UPDATE drivers SET status='en_mission' WHERE id=2
     ✓ INSERT INTO audit_logs (user_id=2, action='CREATE', table='missions', ...)
  → Response: {id: 1, code: 'MS-1693127456000', status: 'planifiee'}
  ✓ Audit log: action='CREATE'
JOUR 2 - Conducteur enregistre départ 
Frontend (Conducteur login) → token: 3, role: 'conducteur'
  ✓ Audit log: action='LOGIN'

Frontend (Click "Départ", collect km/fuel)
  → POST /api/missions/1/departure
  → Backend:
     ✓ Extract token: user_id = 3
     ✓ RBAC: 'conducteur' in ['conducteur']? YES
     ✓ UPDATE missions SET status='en_cours', departure_km=128450, departure_time=NOW() WHERE id=1
     ✓ UPDATE vehicles SET km=128450, engine_hours=4820, fuel_level=82 WHERE id=1
     ✓ INSERT audit_logs (user_id=3, action='UPDATE', table='missions', record_id=1)
  → Response: {ok: true}
  ✓ Audit log: action='UPDATE'
JOUR 3 - Conducteur enregistre retour 
Frontend (Click "Arrivée", collect km/fuel)
  → POST /api/missions/1/arrival
  → Backend:
     ✓ UPDATE missions SET status='retour', arrival_km=128650, arrival_time=NOW() WHERE id=1
     ✓ UPDATE vehicles SET status='en_retour', km=128650, ... WHERE id=1
     ✓ INSERT INTO alerts (mission_id=1, severity='warning', title='Retour - MS-1693...', detail='À vérifier')
     ✓ INSERT audit_logs (user_id=3, action='UPDATE', ...)
  → Response: {ok: true}
  ✓ Alert créée pour Gestionnaire
  ✓ Audit log: action='UPDATE'
JOUR 4 - Gestionnaire valide mission 
Frontend (See alert) → GET /api/alerts
  → Backend: SELECT FROM alerts WHERE read_at IS NULL

Frontend (Click "Valider")
  → POST /api/missions/1/validate
  → Backend:
     ✓ RBAC: 'gestionnaire' in ['admin', 'gestionnaire']? YES
     ✓ UPDATE missions SET status='cloturee' WHERE id=1
     ✓ UPDATE vehicles SET status='disponible' WHERE id=1
     ✓ UPDATE drivers SET status='disponible' WHERE id=2
     ✓ INSERT audit_logs (user_id=2, action='UPDATE', ...)
  → Response: {ok: true}
  ✓ Audit log: action='UPDATE'
Admin review 
Frontend (Admin login) → token: 1, role: 'admin'

Frontend (Click "Audit")
  → GET /api/audit
  → Backend:
     ✓ RBAC: 'admin' in ['admin']? YES
     ✓ SELECT FROM audit_logs ORDER BY created_at DESC LIMIT 500
  → Response: [
       {user_id: 2, action: 'CREATE', table: 'missions', record_id: 1, created_at: '2026-08-27T...'},
       {user_id: 3, action: 'UPDATE', table: 'missions', record_id: 1, details: '{"departure_km":128450}', created_at: '2026-08-28T...'},
       {user_id: 3, action: 'UPDATE', table: 'missions', record_id: 1, details: '{"arrival_km":128650}', created_at: '2026-08-30T...'},
       {user_id: 2, action: 'UPDATE', table: 'missions', record_id: 1, details: '{"status":"cloturee"}', created_at: '2026-08-31T...'}
     ]
  ✓ Complete traceability!
